# 新需求规格：随笔独立目录 + 目录内文件夹（隔离）

用户 2026-09-22：「随笔方面的话就单独给随笔列一个目录，这个目录之后可以在里面创建一些文件夹，
对吧？就把它隔离开来。」——以后还会有别的功能板块（用户原话「以后可能添加其他功能」），
所以随笔要有自己的地盘，不被别的东西搅在一起。

## 1. 目标结构

```
<用户选的可见目录>/            ← SAF 授权根（第一次启动时选）
   └─ mark-readnotes/           ← 应用自建（固定英文名，现有规则不变）
        └─ 随笔/                ← 随笔板块的根（本轮新增；隔离出板块边界）
             ├─ web.md          ← 标签对应的文件（沿用现有规则）
             ├─ paper.md
             └─ 网页随笔/        ← 用户建的文件夹（分类用）
                  └─ blog.md
```

- **一个板块一个目录**：以后加别的功能（例如“剪藏”“任务”）各自一个平级目录，互不干扰。
- 随笔目录里可以**建任意层级文件夹**（用户组织用）。

## 2. 数据模型（谁是权威，必须说清）

| 数据 | 权威 | 说明 |
|---|---|---|
| 块属于哪个**文件** | **第一个标签**（现有规则，不变） | `#web` 的块进 `web.md`；文件名＝标签（ASCII 直用，否则 `t-<sha1前8位>`） |
| 文件放在哪个**文件夹** | SQLite 的 `tag_folder` 映射（tag → 文件夹相对路径） | 文件夹是**标签的一个属性**，可空（空＝直接放 `随笔/` 下） |
| 正文 | 磁盘上的 md 文件 | 索引只缓存 |

**为什么不是“文件自由移动”**：SAF 没有 move/rename 跨目录 API，真正的物理搬家要「复制＋删除」，
中断就会丢内容；改成“标签→文件夹”的映射后，搬家只改一行索引（必要时再做一次物理搬运），可回滚、可审计。
需要动物理文件时（例如把某个标签的文件放进文件夹），实现是「在新位置建同名文件写同内容 → 校验 → 删旧文件」。

## 3. 迁移（expand → migrate → contract，别一步到位）

1. **expand**：升级后第一次启动，如果 `mark-readnotes/随笔/` 不存在 → 创建它；
   同时**兼容**“文件还平铺在 `mark-readnotes/` 根下”的旧布局（索引两个位置都搜）。
2. **migrate**：用户点一次「整理到随笔目录」（或首次进设置页时给一次提示）→ 把根下的 `*.md` 逐个搬进 `随笔/`
   （建新文件→写→校验字节→删旧），日志逐条记；**任何一步失败就停下并如实报**，不做半截。
3. **contract**：等两个版本之后（或用户确认后）不再搜索旧位置。

## 4. 界面（功能 ↔ 板块 ↔ 按键 ↔ 判据）

| 项 | 规格 |
|---|---|
| 入口 | 设置小窗里一行「随笔目录：…」+ 按键「整理到随笔目录」 |
| 新建文件夹 | 设置小窗里「新建文件夹」（输入名字，建在 `随笔/` 下；只允许一层层往下建） |
| 给标签指定文件夹 | 导出小窗/（后续）标签管理里，把某个标签指到某个文件夹（只改索引映射） |
| 判据 | D1：`adb shell ls` 看到 `mark-readnotes/随笔/`；D2：搬完根下不再有 `*.md`，且每个文件的字节与搬前一致（可校验 sha）；D3：搬完主页块数与搬前一致（读 `src.blocks`）；D4：新建文件夹后盘上出现该目录，且库里 `tag_folder` 为空时不改任何文件位置 |

## 5. 本轮不做

- 自由拖拽物理文件（见 §2 的理由）
- 其它板块的目录（先只把随笔隔出来，别的板块建了再加）
- 文件夹的多级权限/加密（加密仓库是后面的事）
