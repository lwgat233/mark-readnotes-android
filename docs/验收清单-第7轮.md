## 为什么要做这一轮（上一轮留下的洞）

第 6 轮把「标签 → 文件夹」做成了映射：**改映射只改索引一行**。
但这样的话，一个标签的文件**已经存在**时：新块会按新映射在文件夹里**另建一个同名文件**，
老的那个留在原地 —— 同一个标签的内容**分裂成两处**，主页看着还是那么多块，盘上却是两个文件。

第 7 轮把这件事补上：**指过去的时候，已有的文件整体跟着走**；目标位置已经有同名文件就**按块合并**。
所以现在的语义是完整的一句：**一个标签 = 一个文件**（不管它在哪个文件夹）。

## 实现要点

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 搬家 | 读源文件 → 在目标目录建/复用文件 → 写 → **读回校验块数** → 才删旧文件 | SAF 没有 move；先写后删保证中断也不丢内容 |
| 索引 | `repointBlocks(旧行 → 新行)` + `dropFile(旧行)` | 块的 id 与「最近编辑」顺序不能丢；不留孤儿行（P16 的教训） |
| 同名合并 | `Md.renderFile(Md.split(目标) + Md.split(源))` 写回目标 | 同一个标签就该是一个文件；合并前后**块数必须对得上**，对不上就停下且不删旧文件 |
| 失败 | 只在 `moveError` 里如实回报，映射仍然生效（界面提示写清“搬家没成功”） | 不半截成功、也不假装成功 |

界面：设置小窗里「指过去」这一个键就把「映射 + 搬家」做完，提示写明搬了几个块、是否并进已有文件。
