## P1 新建块时标签被粘成 `unsortedweb`（已修）

- **现象**：新建块时标签框预填 `unsorted`，用户直接输入 `web` 得到 `unsortedweb`，块被写进 `unsortedweb.md`。
- **根因**：`openBoard(null)` 用 `fillBoard('', DEFAULT_TAG, '')` 预填默认标签，短字段又不全选，输入等于在默认值后面追加。
- **修法**：新块标签预填「上次用过的标签」，没有就留空；标签框聚焦即全选（`focus → select()`）。
- **证据**：`docs/验收清单-第1轮.md` F5。
- **状态**：已修并复验。

## P2 返回键“没反应”的读数存疑（已澄清，非缺陷）

- **现象**：第一次测「按返回键收白板」时读到 `boardOpen=true`。
- **排查**：那一轮前一个动作刚把链接交给系统浏览器，前台曾被打断；当时没有日志可判断是否进到 `onBackPressed`。
  加 `back.enter` / `back.js=` 日志后清干净前台重测 → `back.js="1" handled=true finished=false`，白板关闭、进程不退出。
- **状态**：已澄清（原读数归因于当时前台环境）。

## P5 http 图片被浏览器拦掉，且 compat 模式也不放行（已修，含两个取舍）

- **现象**：`![网络图](http://10.0.2.2:8931/net.png)` 在预览里 `ok:false, 0x0`，本机 HTTP 服务一条请求都没收到。
- **真因**：壳子页面原本是 `https://appassets.androidplatform.net`，其上的 http 图片属于混合内容，
  Chrome 对**图片**按“可拦截”处理（自动升级失败即拦）。页面控制台原话：
  `Mixed Content: … requested an insecure image 'http://…'. This request has been blocked; the content must be served over HTTPS.`
  —— 把 `mixedContentMode` 改成 `MIXED_CONTENT_COMPATIBILITY_MODE` 也**不放行**（实测仍拦）。
- **修法（两个显式取舍）**：
  1. 壳子改走 **http 虚拟源**（`http://appassets.androidplatform.net`，仍是本地拦截、不出网）→ 不再存在混合内容；
     代价：页面不是安全源（本项目不用 `crypto.subtle`/service worker 这类需要安全源的能力）。
  2. 清单加 `android:usesCleartextTraffic="true"`（否则 Android 9+ 明文请求直接被平台拦）。
- **证据**：`docs/验收清单-第2轮.md` F10（`ok:true, 64×64` + 服务端日志 `GET /net.png 200`）。
- **状态**：已修并复验。

## P7 我自己把两个源文件写空了（代码事故，已恢复）

## P8 干净重建“内容一致、整包 sha256 不一致”（不是缺陷，是打包差异，已写清口径）

- **做法**：把 git 里的源码快照导到干净目录重建（`bash tools/verify-repro.sh`），与归档构件对比。
- **实测**：`BUILD SUCCESSFUL`；两次产物的 **69 个条目逐条 CRC/原始大小/压缩大小完全一致**，
  但**整包 sha256 不同**（归档件 1,682,853 字节 vs 重建件 1,634,877 字节）。
- **查到的原因**：差异不在条目内容，而在 zip 的打包期结构 —— 首个不同字节出现在某个 local file header 的
  extra 字段长度（16 vs 20），随后每条的偏移被对齐填充带偏，累计差约 48KB。
- **口径（写进验收与 README）**：整包 sha256 只用来标识“交付的就是这一份”；
  **“源码可复现”用条目级对比来证**（`tools/verify-repro.sh` 会直接打出“内容不一致条目: 0”）。
  不把“哈希一致”当复现门槛，也不在没有证据的情况下声称可复现。
- **状态**：口径已定，脚本已归档（`tools/verify-repro.sh`）。

## P15 逐个 token 消毒会把成对的行内 HTML 拆散（第 5 轮开发中发现并修好）

- **现象**：`<span style="color:red">带颜色的 span</span>` 渲染成
  `<p><span style="color:red"></span>带颜色的 span</p>` —— span 变空、文字被挤到标签外面。
- **真因**：markdown-it 把行内 HTML 拆成两个 token（开始标签一个、结束标签一个）。
  用 `<template>` 逐个 token 解析时，浏览器会把没闭合的开始标签自动补成 `<span …></span>`，
  孤立的 `</span>` 又被丢掉 —— 标签对就散了。
- **修法**：行内 HTML 不在 token 层动；改成**整段一起解析**（游离容器）→ **整体消毒** → 再挂进页面。
  副产品：先消毒后上屏，危险的标签/属性在接触真实文档之前就已经没了。
- **回归判据**：`boards/render.sh` 的 `R5 行内 HTML 里的文字没被挤到标签外`（读 span 的 textContent）。
- **状态**：已修（渲染板块 29 绿 0 红）。

## P16 整理旧布局会把块在索引里变成两份（第 6 轮开发中发现并修好）

- **现象**：点「整理到随笔目录」后，块数从 8 变成 **15**（正好多一份）；文件内容本身没错。
- **真因**：搬家是「在新位置建文件 → 写 → 删旧文件」，新文件的 docUri 变了 → 索引里多出一个 `note_file` 行；
  旧行名下的块行既没改指也没标掉 → 下次扫描给新行重新入库一遍块，**旧行那份还留着**，于是重复。
- **修法**：搬家后 `repointBlocks(旧行 → 新行, 新 docUri)`（保住块的 id 与「最近编辑」顺序），再 `dropFile(旧行)`；
  另外给 `refresh` 补一条一致性收尾：文件不在了，它名下的块一起标成不在（不留孤儿块）。
- **回归判据**：`boards/store.sh` 的 `store.migrate 搬完块数没变（D3）`、`store.migrate 该文件的块都在（D3）`。
- **状态**：已修（存储板块 23 绿 0 红）。

## P18 只映射不搬家 → 同一个标签的内容分裂成两个文件（第 7 轮修好）

- **现象**（由第 6 轮的设计审查发现，不是崩溃）：把一个**已经存在文件**的标签指到文件夹之后，
  新块按新映射在文件夹里建了同名文件，**老文件留在原地** —— 一个标签两份文件，主页看不出异常。
- **真因**：`ensureFileForTag` 只看映射算目标相对路径；老文件的行还在索引里（位置不同），
  于是一边是「老文件继续被读写」，一边是「新文件被建出来」。
- **修法**：改映射时**顺带把已有文件搬过去**（`moveTagFile`）：复制 → 读回校验块数 → 删旧 → `repointBlocks` → `dropFile`；
  目标位置已有同名文件时**按块合并**（`Md.renderFile(split(目标) + split(源))`），合并前后块数必须相等，否则停下且不删旧文件。
  语义收敛成一句：**一个标签 = 一个文件**。
- **回归判据**：`boards/store.sh` 的 D5 段（`store.move *`、`store.merge *`，共 14 条）。
- **状态**：已修（存储板块 37 绿 0 红）。

## P19 WebDAV 自测抓出的四个真缺陷（第 8 轮，全部修好）

都是**自己写的两端**（客户端 + 验收用的服务）的 bug，靠 `tools/dav-selftest.py` 与真机联调抓出来的：

- **服务端没剥挂载前缀**：配置 `/dav` 时把请求路径 `/dav/xxx` 当成文件相对路径 → 文件落进 `root/dav/`，
  客户端列目录永远 404。修：`fs_path` 先剥前缀。
- **href 拼进了“列哪个目录”**：`/dav/随笔/随笔/web.md`。修：href 的 base 用挂载前缀，不用请求路径。
- **二次编码**：对已编码的请求路径又 `quote` 一遍 → href 里出现 `%25`。修：先 `unquote` 再整体编码一次。
- **第一次同步必然失败**：远端还没有 `随笔/` 目录时 `PROPFIND` 回 404，客户端把它当错误。
  修：404 = “远端还没有这个目录”（当空），其它状态码才算错。

判据留在 `tools/dav-selftest.py`（16 条，含二次编码与越界）。

## P20 客户端解析 href 不能写死路径（真机经验，已按通用做法改）

PROPFIND 返回的 href 要按**用户填的 base 路径**去截，不能写死 `/dav`：
Nextcloud 这类是 `/remote.php/dav/files/<user>`，写死就会把整段路径当成文件名。
实现里用 `basePath = URI(base).path` 参与解析。

## P21 增量构建出来的构件复现不了（第 8 轮收尾时抓到，已按干净构建重新归档）

- **现象**：用 `tools/verify-repro.sh` 校验 r8 归档时，**89 个条目里有 3 个 dex 内容不一致**
  （`classes3/4/5.dex`）；而以前各轮的条目级校验都是 0 不一致。
- **判定过程**：连跑两次干净副本重建 → **两次结果逐字节相同**（同一个 sha256）
  → 说明不是“构建不可复现”，而是**归档那一份是工作目录里反复增量构建出来的**，
  增量 dex 合并的字节与从头构建不同。
- **处置**：清掉 `app/build` 从头构建一次（结果与干净副本构建逐字节相同），**用这一份重新归档**，
  在它上面把六板块重新跑一遍（122 条全绿），并确认 `adb pull` 回来的、设备上装的
  APK 与归档件 **sha256 一致**（跑验收的就是归档那一份）。
- **现在的口径**：归档 = **干净构建产物**；复现校验要求**条目级 0 不一致**，
  整包 sha256 也相同（`evidence/verify-repro-r8.txt`）。`tools/verify-repro.sh` 的收尾判定
  已按结果分三种说法打印（可复现 / 仅整包不同 / 不可复现并给出处置）。
- **教训**：**归档前先清一次 `app/build` 再从零构建**，别把增量产物当交付件；
  校验发现 dex 不一致时，先跑两次干净构建看彼此是否一致，再决定是“环境不可复现”还是“归档件不对”。

- **现象**：`verify-board.sh` 在装包前打印「构件里没有 MainActivity，别装！」并 `return 4`，
  **整轮分板块验收一条都没跑**；而我随后读到的“六板块全绿”其实是**上一轮留下的旧证据文件**（差点当成这一轮的）。
- **真因**：那个自毁守卫（P7 事故后加的）写死了 `unzip -p "$APK" classes3.dex` 再找启动类。
  这一轮加了 OkHttp，**启动类从 `classes3.dex` 挪到了 `classes5.dex`**（实测命中 2 次）→ 守卫误判。
- **修法**：遍历构件里**所有** `*.dex` 再统计命中数；命中 0 才拦，并把命中数打印出来（`构件里有启动类（命中 N 次）`）。
- **配套教训**：**读证据文件时要看时间戳**（`ls -l --time-style=+%H:%M:%S evidence/board-*.txt`），
  否则会把上一轮的结果当成本轮的；这次就是靠这一步发现的。
- **状态**：已修；随后重跑六板块 122 条全绿，并确认设备上装的 APK 与归档件 sha256 一致。

## P23 验收残留会变成“幽灵冲突”；以及空变量 + 通配符的 rm 有多危险（第 8 轮收尾）

- **现象**：存储板块 D5 造的两个验收文件（`movetestNNN` / `mergetestNNN`）**每轮留在本地**，
  被同步板块传上远端后本地又被删掉 → 远端还在 → **你下次同步会看到 2 个“本地已删除，远端还在”的冲突**，
  看着像同步坏了，其实是验收残留。
- **修法（两层）**：① 存储板块收尾把这两个文件连块一起删掉，并断言盘上确实没了（`store 收尾 验收文件都清掉了`）；
  ② 同步板块收尾把远端各种验收文件名（`movetest* / mergetest* / syncup* / remoteonly* / conflict-* / legacyboard-*`）
  在 `随笔/` 与 `随笔/boardfolder/` 下一起清掉，并断言**紧接着的计划里冲突数 = 0**（`sync 收尾 没有幽灵冲突`）。
  已清过的历史残留（远端 `mergetest181443` 等）一并清掉。
- **顺带记一条脚本红线**：第一版收尾里我写了 `rm -f "$DAV_ROOT/随笔/$FOLDER"/*.md`，
  而 `$FOLDER` 在同步板块里是**空变量** → 会删掉整个远端目录。改成显式目录名 + 逐个模式清理
  （`for d in ...; do for pat in ...; do rm -f "$d/$pat"*.md; done; done`）。
  **规矩：删除类命令里不许把可能为空的变量拼进带通配符的路径。**
- **状态**：已修；存储 39 条、同步 25 条全绿（六板块合计 124 条）。
