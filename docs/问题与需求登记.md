# 问题与需求登记（mark-readnotes）

格式：现象 / 根因 / 修法 / 证据 / 状态。新的往下加。

## P1 新建块时标签被粘成 `unsortedweb`（已修）

- **现象**：新建块时标签框预填 `unsorted`，用户直接输入 `web` 得到 `unsortedweb`，块被写进 `unsortedweb.md`。
- **根因**：`openBoard(null)` 用 `fillBoard('', DEFAULT_TAG, '')` 预填默认标签，短字段又不全选，输入等于在默认值后面追加。
- **修法**：新块标签预填「上次用过的标签」，没有就留空；标签框聚焦即全选（`focus → select()`）。
- **证据**：`docs/验收清单-第1轮.md` F5。
- **状态**：已修并复验。

## P2 返回键“没反应”的读数存疑（已澄清，非缺陷）

- **现象**：第一次测「按返回键收白板」时读到 `boardOpen=true`。
- **排查**：那一轮前一个动作刚把链接交给系统浏览器，前台曾被打断；当时没有日志可判断是否进到 `onBackPressed`。
  加 `back.enter` / `back.js=` 日志后清干净前台重测 → `back.js="1" handled=true finished=false`，白板关闭、进程不退出。
- **状态**：已澄清（原读数归因于当时前台环境）。

## P3 SAF 不能选存储根目录（设计已适配）

- **现象**：`ACTION_OPEN_DOCUMENT_TREE` 停在内置存储根，系统显示 "Can't use this folder"。
- **处置**：引导用户选一个子目录（如 Documents），应用在其中**自建** `mark-readnotes`（目录名固定英文）。
- **状态**：已按此设计实现（第 1 轮 F1）。

## P4 模拟器 AVD `test34` 起不来（环境问题）

- **现象**：容器 7 秒 `Exited (1)`，日志 `Failed to process .ini file …/test34.avd/config.ini` + `FATAL | CPU Architecture 'arm' is not supported`。
- **根因**：`test34.avd/` 下缺 `config.ini`，模拟器落到默认（arm）配置。
- **处置**：改用 `test35`（x86_64 / android-34）。已写进 skill。
- **状态**：绕过。

## P5 http 图片被浏览器拦掉，且 compat 模式也不放行（已修，含两个取舍）

- **现象**：`![网络图](http://10.0.2.2:8931/net.png)` 在预览里 `ok:false, 0x0`，本机 HTTP 服务一条请求都没收到。
- **真因**：壳子页面原本是 `https://appassets.androidplatform.net`，其上的 http 图片属于混合内容，
  Chrome 对**图片**按“可拦截”处理（自动升级失败即拦）。页面控制台原话：
  `Mixed Content: … requested an insecure image 'http://…'. This request has been blocked; the content must be served over HTTPS.`
  —— 把 `mixedContentMode` 改成 `MIXED_CONTENT_COMPATIBILITY_MODE` 也**不放行**（实测仍拦）。
- **修法（两个显式取舍）**：
  1. 壳子改走 **http 虚拟源**（`http://appassets.androidplatform.net`，仍是本地拦截、不出网）→ 不再存在混合内容；
     代价：页面不是安全源（本项目不用 `crypto.subtle`/service worker 这类需要安全源的能力）。
  2. 清单加 `android:usesCleartextTraffic="true"`（否则 Android 9+ 明文请求直接被平台拦）。
- **证据**：`docs/验收清单-第2轮.md` F10（`ok:true, 64×64` + 服务端日志 `GET /net.png 200`）。
- **状态**：已修并复验。

## P6 白板把小窗盖住，「删除本块」点不到（已修）

- **现象**：在白板里点「⋯」→ 小窗出现但点「删除本块」毫无反应（按钮文字也不变确认态）。
- **真因**：`#sheet` z-index 50 < `#board` z-index 60 —— 全屏白板盖在小窗之上，
  手指落在白板那一层（`elementFromPoint` 给的是白板的元素），小窗里的键根本没收到点击。
- **修法**：`#sheet` 提到 70（它就是从白板里点开的，必须在上层）。
- **证据**：`sheetZ=70 / boardZ=60`，`elementFromPoint(206,228) → BUTTON|删除本块`；
  两次点击后块从卡片列表与 md 文件里消失。见 `docs/验收清单-第2轮.md` F12。
- **状态**：已修并复验。

## P7 我自己把两个源文件写空了（代码事故，已恢复）

- **现象**：改版本号的脚本写成 `open(p,'w').write(open(p,'r').read().replace(...))` ——
  `open(p,'w')` 先执行就把文件**截断**了，参数再读回空串，于是 `MainActivity.kt` 与 `index.html` 变成 0 字节。
  构建照样“成功”（清单里的类名不会在编译期校验），装上去一启动就崩：
  `ClassNotFoundException: Didn't find class "dev.markreadnotes.MainActivity"`。
- **修法**：从 git 取回这两个文件（上一次提交的版本），再用逐条 patch 重新打上第 2 轮的改动；
  构建后**先证明构件里有这个类**（`unzip -p apk classes3.dex | strings | grep -c Ldev/markreadnotes/MainActivity;`）再安装。
- **教训**：批量改文件一律走 patch 工具或「先读进变量、再单独写回」，绝不把读写塞进同一个表达式；
  启动崩先看 `AndroidRuntime` 的 `ClassNotFoundException`，那是“包不对”而不是“代码逻辑错”。
- **证据**：恢复后 `MainActivity.kt` 202 行 / `index.html` 59 行；r4 构件启动日志
  `app.start build=0.1.0+r4 scan=skipped(reason=startup)`，无崩溃。
- **状态**：已恢复并复验。

## P8 干净重建“内容一致、整包 sha256 不一致”（不是缺陷，是打包差异，已写清口径）

- **做法**：把 git 里的源码快照导到干净目录重建（`bash tools/verify-repro.sh`），与归档构件对比。
- **实测**：`BUILD SUCCESSFUL`；两次产物的 **69 个条目逐条 CRC/原始大小/压缩大小完全一致**，
  但**整包 sha256 不同**（归档件 1,682,853 字节 vs 重建件 1,634,877 字节）。
- **查到的原因**：差异不在条目内容，而在 zip 的打包期结构 —— 首个不同字节出现在某个 local file header 的
  extra 字段长度（16 vs 20），随后每条的偏移被对齐填充带偏，累计差约 48KB。
- **口径（写进验收与 README）**：整包 sha256 只用来标识“交付的就是这一份”；
  **“源码可复现”用条目级对比来证**（`tools/verify-repro.sh` 会直接打出“内容不一致条目: 0”）。
  不把“哈希一致”当复现门槛，也不在没有证据的情况下声称可复现。
- **状态**：口径已定，脚本已归档（`tools/verify-repro.sh`）。
