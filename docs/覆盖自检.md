# 覆盖自检（自动比对：登记表 vs 界面 DOM vs 测试映射）

跑法：

```
python3 tools/check_coverage.py --strict      # 文件层面（登记 vs 测试脚本是否存在）
# 界面层面：打开应用后读 window.__coverage（selfcheck.js 自动跑一次）
node tools/webview-cdp.mjs eval 'window.__coverage'
```

## 最近一次结果（2026-09-22，构件 `0.1.0+r6`）

```
登记：板块 6 个；功能 23 个（已实现 21，计划中 2）
  没归属: 0
  空集合: 0
  没测: 0
  脚本不存在: 0
  未做: 2 → ['store.folder', 'sync.webdav']
缺口合计：2
```

- 阻塞类缺口（没归属 / 空集合 / 没测 / 脚本不存在）**全为 0** → `--strict` 退出码 0，可当回归门禁。
- 剩下的 2 项是**计划中的功能**（随笔独立目录、WebDAV），按 skill 的规矩：
  `planned` 不进界面，只在自检里点名，做完当场把状态改成 `done`。

## 七类缺口的含义（自检报的就是这些）

| 类别 | 判定 | 处理 |
|---|---|---|
| 没归属 | 功能的 `board` 不在板块表里 | 补板块或改归属 |
| 空集合 | 板块下一个功能都没有 | 删板块或补功能 |
| 界面空集合 | 板块里的功能全是 planned，界面上空着 | 要么做，要么别占位 |
| 没挂上 | `status=done` 但 DOM 里查不到 `testId` | 真缺控件 → 补；选择器写错 → 改登记 |
| 没测 | 没写 `test`，或写了但脚本不存在 | 补 `tools/boards/<板块>.sh` |
| 未做 | `status=planned` | 待办清单（用户说的“开发不足”就是这张表） |
