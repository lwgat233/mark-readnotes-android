## 数据流（改造后）

```
正文 md
  → markdown-it（html:true, linkify:true）          ← 内置 vendor/markdown-it
  → texmath 只负责认出分隔符，公式 HTML 由 KaTeX 出  ← 内置 vendor/markdown-it-texmath + katex
  → task-lists 产出勾选框                          ← 内置 vendor/markdown-it-task-lists
  → html_block token 过白名单（template 解析，惰性，脚本不执行）
  → 整段放进游离容器解析并整体消毒（成对标签才对得上）
  → 挂进 #preview（先消毒、后上屏）
  → 统计写进 window.__render / __sanitize / __tex（验收读的就是这三个）
```

## 本轮改出的两个真缺陷（都修了）

### P15 逐个 token 消毒会把成对的行内 HTML 拆散

- **现象**：`<span style="color:red">带颜色的 span</span>` 渲染成
  `<p><span style="color:red"></span>带颜色的 span</p>` —— span 空了、文字被挤到标签外面。
- **根因**：markdown-it 把行内 HTML 拆成两个 token（开始标签一个、结束标签一个）。
  用 `<template>` 逐个 token 解析时，浏览器会把「没有闭合的开始标签」自动补成 `<span …></span>`，
  而孤立的 `</span>` 又会被丢掉 —— 于是标签对散了。
- **修法**：行内 HTML 不在 token 层动；改成**整段一起解析**（游离容器）后**整体消毒**，再挂进页面。
- **回归判据**：`R5 行内 HTML 里的文字没被挤到标签外`（断言 span 的 textContent 必须是 `带颜色的 span`）。

### P13 原始 HTML 里的相对图片路径不走 `/file/`（第 4 轮登记，本轮顺手修好）

- 消毒阶段对白名单里保留的 `img` 统一重写 `src`（相对路径 → `/file/<相对路径>`），
  于是 `<img src="pic.png">` 与 `![](pic.png)` 两种写法都出图（实测都是 64px）。
