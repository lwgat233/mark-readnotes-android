# 开发计划（第 9 轮重设，2026-09-22）

用户原话：**「你的身份是功能创造者，不是渲染者。你先停一下了，再思考一下，重新设置一下计划。」**

## 0. 身份与口径（先立规矩，再排活）

- **我是功能创造者**：一轮的产出是**一个能用的功能**（入口 + 调用 + 判据 + 文档四件齐），不是界面打磨。
- **渲染只做最小件**：只有当某个功能本身需要渲染时才改 `render.js`/样式；不为"好看"单独开轮。
- **一轮一个功能**，做完做透再进下一个；允许跨层（前端 + op + repo），但不许"半成品留在树上"。
- **只测改动**：跑该功能所属板块的判据；**全量只在该轮归档时跑一次**。
- **不另写文档**：每轮只更新三处 —— `assets/ui/registry.js`（登记）、`docs/功能调用与意义.md`（调用与意义）、该板块判据脚本。
- **归档口径**（每轮收工）：清 `app/build` 从零构建 → 该板块判据全绿 → sha256 → `apk/` 里一份 → commit + push。
- **不做**（用户已拍板或明确不相关）：左侧栏、S3/Syncthing、Quillpad 富文本、换图标、多语言、检查更新；
  思维导图 / 手绘板 / 录音附件 暂缓（与"阅读随笔"关系不大）。

## 2. 每轮的固定动作（照抄，别自由发挥）

1. 读一眼 `docs/问题与需求登记.md` 和 `/vol1/1000/mydoc/log.md`（有没有新需求）。
2. 动手实现（前端 + op + repo），**每步 `node --check` / `assembleDebug` 验证**。
3. 给这个功能写判据（该板块脚本加一段，命名 `板块.功能 判据名`），跑该板块。
4. 更新 `registry.js`（status=done，带 testId 与 test）与 `docs/功能调用与意义.md`（一行：入口 → 调用 → 意义 → 判据）。
5. 归档：清 `app/build` 从零构建 → `apk/` 命名落一份 → sha256 → commit + push。
6. 收尾：停模拟器、停测试服务、清验收残留（P23 的规矩）。
