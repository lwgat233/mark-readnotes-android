# 渲染规格（第 4 轮的重点：把手写渲染器换掉）

用户 2026-09-22：「重点重构的是那个渲染，你的 markdown 现在其实不太好」。
参照对象：`waikr/KardLeaf` 的 `app/src/main/assets/preview/preview.html` +
`markdown-it.min.js` / `markdown-it-texmath.min.js` / `markdown-it-task-lists.min.js` / `preview-html-sanitizer.js`
（MIT，全部可离线内置；它也是 WebView 渲染，跟我们同架构）。

## 1. 现在的渲染器差在哪（自己实测出来的，不是感觉）

现在 `assets/ui/app.js` 里的 `renderMd()` 是我手写的 ~60 行，逐行匹配：
- 没有**表格**（`| a | b |` 会变成一段普通文字）
- 没有**任务清单**（`- [x] 做完` 只是普通列表项，方括号裸露）
- 没有**嵌套列表**（缩进层级丢了，全变同级 `<ul>`）
- 没有 **YAML front matter** 处理（`---` 会被当成分割线）
- 没有 **wikilink**（`[[笔记]]` 原样显示）
- 没有**转义/软换行/脚注/自动链接/定义列表**等常见语法
- HTML 只做“放行 + 事后删危险节点”，没有**属性白名单**（如 `style="color:#f00"` 该不该留没定）
- 公式虽接了 KaTeX，但只认 `$…$` 与 `$$…$$`，`\(…\)` / `\[…\]` / 多行块是我后来补的补丁
- 预览是**一次性渲染**：没有实时预览、没有“点预览跳到源码对应位置”

## 2. 目标（第 4 轮做完的样子）

| 项 | 规格 |
|---|---|
| 渲染引擎 | 内置 **markdown-it**（MIT）替换手写渲染器；公式走 **markdown-it-texmath** + 已内置的 KaTeX；任务清单走 **markdown-it-task-lists**（MIT） |
| 资源方式 | 与 KaTeX 一样：放 `assets/ui/vendor/`，**离线内置**；拉包时校验 npm 声明的 integrity，来源与哈希写进 `evidence/` 与 `THIRD-PARTY-NOTICES.md` |
| 消毒 | 用 markdown-it 的 `html_block`/`html_inline` 规则把原始 HTML 先过白名单（参考 KardLeaf 的 `preview-html-sanitizer.js` 思路）：标签白名单 + 属性白名单（`#hex` 颜色、有限字号），`on*`/`javascript:`/`script/iframe/object/embed` 一律去掉 |
| 资源引用 | 图片/链接规则不变（相对路径走 `/file/`，带协议的直链交给 WebView）——这是回归项，不许被改坏 |
| 渲染计数 | 页面自报 `window.__render = {blocks, tables, tasks, katex, htmlKept, htmlDropped, ms}`，验收读它 |
| 不做（本轮） | 实时预览、编辑↔预览锚点定位（下一轮）、代码高亮（可选） |

## 3. 判据（第 4 轮，全部读回来的事实）

用一段“全覆盖”试块（表格+任务+嵌套列表+公式+脚本+相对图片）在设备上渲染，断言：

| 编号 | 功能点 | 判据 |
|---|---|---|
| R1 | 表格 | `#preview table` 存在，行数列数与 md 一致（读 `rows/cells`） |
| R2 | 任务清单 | `#preview input[type=checkbox]` 数量对；勾选态与 `[x]` 一致 |
| R3 | 嵌套列表 | 二级列表的父节点是 `li`（读 DOM 父子链），层级数=2 |
| R4 | 公式 | `.katex` 数 = 公式数；`$E=mc^2$` 与 `$$…$$`、`\(…\)`、`\[…\]` 四种写法都出 DOM；坏公式出 `.katex-error`，页面不炸 |
| R5 | HTML 白名单 | `<div style="color:#ff0000">` 保留且 style 只剩允许项；`<script>`/`iframe`/`onerror`/`javascript:` 全无（`__sanitize` 计数 > 0） |
| R6 | 代码块 | 围栏代码里的 `#`、`*`、`$` 不被解析（读 `pre` 文本与 md 一致） |
| R7 | 回归 | 现有 6 个块的渲染不报错（页面 console 无异常），图片仍 `naturalWidth>0` |
| R8 | 性能 | 渲染上述试块 `ms` < 200（读 `__render.ms`），且页面无卡顿（帧数不测，只测渲染耗时） |
| R9 | 出处 | `THIRD-PARTY-NOTICES.md` 与 `evidence/` 里能查到每个前端库的来源与校验；代码注释里有 `参考 waikr/KardLeaf` 标记 |
