# 功能调用与意义（每个功能：从哪个界面进去、调什么、什么参数、返回什么、到底解决什么）

用户要求（2026-09-22）：**「你要写出每个功能的调用和意义」**。这份文档就是这句话的交付：
每个功能一行，左边是「界面上怎么进」，中间是「调用与返回」，右边是「意义（它解决什么）」。
功能清单的唯一权威源是 `assets/ui/registry.js`（29 项，板块 A–F），本文件与它一一对应。

---

## 0. 调用通道（所有功能都走同一套，没有例外）

```
界面/按键
  └─ 前端：call(op, args)                       // assets/ui/core.js，返回 Promise
        └─ window.mrbridge.postMessage(JSON.stringify({id, op, args}))
              └─ 原生：OpsRouter.dispatch(raw)  // ops/OpsRouter.kt
                    ├─ 按板块分发：ops/*.kt（AppOps/SourceOps/BlockOps/ExportOps/SyncOps/UiOps）
                    └─ 落到 repo：NotesRepo / ExportRepo / SyncRepo（SAF、SQLite、OkHttp）
        ← 回包：window.mrpush("{id, ok:true, data}")  → Promise 兑现
                window.mrpush("{id, ok:false, error}") → Promise 拒绝
```

- **命名**：`板块.动作`。`app.*` 应用信息｜`src.*` 授权与目录｜`idx.*` 索引｜`blk.*` 块（随笔本体）｜
  `exp.*` 导出｜`sync.*` 同步｜`ui.*` 交给系统的动作（打开链接、分享）。
- **回包约定**：成功 `{ok:true, data}`，失败 `{ok:false, error}`（`OpsRouter` 统一包）。
  前端 20 秒无回包即报 `op 超时：<op>`。另有**主动推送** `{type, data}`（如首次启动要求选目录）。
- **为什么这样设计（意义）**：**一件事一个 op**，界面与外部控制口（验收脚本、以后的控制台）共用同一套调用 ——
  于是「界面上验过的，就等于接口验过的」。验收脚本就是直接调这些 op 造状态、再读回结果判定的，
  所以下面每个功能的「判据」都真跑过这些调用。

## 1. 板块 A：随笔（`blk.*` / `idx.*`）—— 载体：主页 + 全屏白板

| 功能 | 界面入口 | 调用（参数 → 返回） | 意义 | 判据 |
|---|---|---|---|---|
| 主页列出最近编辑的块 | 打开应用 | `idx.blocks{limit}` → 块数组（字段同 `blk.get`），按最近编辑排在前面 | 打开就能接着上次写；索引在 SQLite 里，**不 walk 目录** | `notes.sh#home` |
| 新建块 | 主页底部「＋ 新随笔」 | `blk.new{tag,heading,body}` → `{id, file, tag}` | 一个块 = 一级标题 + 标签行 + 正文；新建即落盘（文件是权威源） | `notes.sh#new` |
| 全屏白板编辑 | 点卡片 | `blk.get{id}` → `{id,heading,tags[],tag,file,relPath,folder,updatedAt,charCount,body}` | 编辑要有整屏空间；读完的字段就是白板要显示的全部状态 | `notes.sh#board` |
| 归档区：标题+标签与正文隔离 | 白板顶部 | 保存时 `blk.save{id,heading,tags[],body}` → 该块保存后的落位 | 标题和标签**不混进正文**，正文里就不会被标签行污染 | `notes.sh#arch` |
| 改第一个标签＝整块搬家 | 白板标签框 | 同上 `blk.save`；内部：新文件写入 → 索引 `repointBlocks` → 旧文件 `dropFile` | 「一个标签＝一个文件」：改第一个标签就把**整块**挪到那个标签的文件里 | `notes.sh#move` |
| 删除本块（两次确认） | 白板「⋯」 | `blk.delete{id}` → `{id, deleted}` | 删的是块不是文件；文件空了才收走 | `notes.sh#delete` |

## 2. 板块 B：渲染（预览层，前端 `render.js`）—— 载体：白板里的预览层

> 渲染**不走 op**：正文直接在前端渲染（内置 `markdown-it` + `markdown-it-texmath` + 任务清单插件 + 内置 KaTeX）。
> 调用面是前端函数 `renderInto(容器, markdown 文本, baseDir)`，`baseDir` 用来把相对图片路径重写成可读地址。
> 唯一走 op 的是「点链接」：`ui.open{url}` → `{opened}`（交给系统浏览器，不在预览层内导航）。

| 功能 | 入口 | 调用与关键判据 | 意义 |
|---|---|---|---|
| markdown 渲染（标题/列表/引用/代码/表格） | 白板「预览」 | `renderInto()`；判据查 DOM：`h2/h3/h4` 各 1、引用 1 块、表格 1、`ol` ≥1 | 随笔是读网页/论文来的，md 得真能读 |
| 表格 | 同上 | 表格外套 `.table-scroll`（宽表横向滚动），圆角只画外框、单元格只画右下边框 | 宽表不撑破页面 |
| 任务清单（勾选框） | 同上 | 判据 `checked=1`（`[x]` 真勾上）、`input[type=checkbox]` 存在 | 读完一篇文章的待办能直接勾 |
| 嵌套列表 | 同上 | 判据嵌套层级 ≥2 | 论文的层级结构能表达 |
| 数学公式（四种写法） | 同上 | `$$..$$`、`\[..\]`、`$..$`、`\(..\)` 四种都认；判据查 `.katex` | 论文里的公式要能看 |
| 图片（md 与原始 HTML 两种写法） | 同上 | `img.src` 统一重写成可读地址；判据 `naturalWidth>0`、`img[width=64]` | 网页截图/配图能显示 |
| 基本 HTML 白名单消毒 | 同上 | 白名单过滤；判据：放行 `div.note`、挡掉 `script/iframe/on*` | 笔记里的 HTML 不能变成能乱动文件的代码 |
| 链接跳转 | 点链接 | `ui.open{url}` → `{opened}` | 随笔里记的网页要能一键回去看 |

## 3. 板块 C：存储（`src.*` / `idx.*`）—— 载体：主页「设置」小窗

| 功能 | 入口 | 调用（参数 → 返回） | 意义 | 判据 |
|---|---|---|---|---|
| 目录授权（SAF 持久授权） | 设置「重新选择目录」 | `src.pick` → `{pending}`（真选完由推送回填）；`src.get` → `{has,treeUri,pickedName,rootLabel,nodeLabel,node,files,blocks,lastScanAt,tagFolders,tag,folder,legacy,legacyNames,exportRoot}` | 记在哪、能不能写，一次授权长期有效 | `store.sh#auth` |
| 懒扫描索引（冷启动不扫目录） | 冷启动 | 不 walk；要刷才 `idx.refresh` → `{files, blocks}`；`idx.stats` 同上 | 索引常驻 SQLite，**网络存储也不扫全目录**（这是当初点名的要求） | `store.sh#scan` |
| 写回 md（文件是权威源） | 保存块 | `blk.save{...}` | 正文永远是磁盘上那份 md，SQLite 只是索引 | `store.sh#write` |
| 随笔目录里的文件夹 | 设置「新建文件夹」 | `src.mkdir{relDir}` → `{docId, folder, rel}` | 随笔单独一个目录，还能再分层 | `store.sh#folder` |
| 一个标签一个文件 | 设置「标签 → 文件夹」 | `src.setTagFolder{tag,folder}` → `{tag, folder, move, moveError}`；搬文件用 `moveTagFile` → `{skipped}` | 改了映射，**已有文件也得跟着搬**，否则同标签分裂成两个文件 | `store.sh#move` |
| 整理旧布局 | 设置（有待整理时才出现） | `src.migrate` → 搬移结果 | 老版本落在根下的 md 搬进随笔目录；搬完块数不变、不留重复 | `store.sh#migrate` |

## 4. 板块 D：导出（`exp.*`）—— 载体：主页「导出」小窗

| 功能 | 入口 | 调用（参数 → 返回） | 意义 | 判据 |
|---|---|---|---|---|
| 按标签导出 | 主页「导出」 | `exp.tags` → 标签统计；`exp.plan{exclude[]}` → `{files[], dirs[], count, excluded, exportRoot}` | 目录层级＝标签顺序（第1标签一级目录、第2标签二级…），导出的目录用标签原文 | `export.sh#plan` |
| 排除标签 | 点标签芯片 | 同上，`exclude` 数组 | 私事/草稿不导出 | `export.sh#exclude` |
| 导出并预览（不写盘） | 「导出并预览」 | `exp.plan{exclude[]}` | 先看要写哪些文件，别乱写盘 | `export.sh#preview` |
| 写入目录（覆盖不堆副本） | 「写入目录」/「直接导出」 | `exp.writeDir{exclude[]}` → 新建/更新的计数 | 同名覆盖，不会堆出 `-2` 副本 | `export.sh#write` |
| 系统分享 | 「系统分享」 | `exp.share{exclude[]}` | 导给别人（微信/邮箱） | `export.sh#share` |

## 6. 板块 F：同步（`sync.*`）—— 载体：设置 → WebDAV 小窗

| 功能 | 入口 | 调用（参数 → 返回） | 意义 | 判据 |
|---|---|---|---|---|
| WebDAV 配置与连接测试 | WebDAV 小窗 | `sync.get` → `{ok, url, user, hasPass, message, syncedFiles}`；`sync.set{url,user,pass}` → `{ok,message}`；`sync.test` → `{ok,message}` | 自己的 NAS 当同步端，不依赖第三方 | `sync.sh#config` |
| 计划（先看差异再动手） | 「立即同步」前 | `sync.plan` → `{items[{relPath, action}], conflicts[], …}` | 本地/远端差异先摊开，**不偷偷改文件** | `sync.sh#plan` |
| 执行同步 | 「立即同步」 | `sync.run` → `{uploaded, downloaded, conflicts, reason}` | 双向补齐；冲突就停下来问 | `sync.sh#run` |
| 冲突三选（保留本地/保留远端/跳过） | 冲突行上的键 | `sync.resolve{relPath, choice}` → `{relPath, choice, done, pending}` | 两边都改过时由人决定，**跳过之后下次还会报** | `sync.sh#conflict` |

## 9. 红线（写死在这里，改动时对照）

1. **一件事一个 op**；界面上做的事必须能通过 op 复现（不然验收脚本没法测，也就等于没测）。
2. 返回一律 `{ok, data}` / `{ok, error}` 两态；**失败要带话**，不许静默成功。
3. `planned` 的功能**不许出现在界面上**（会变成点不动的空块）。
4. 笔记内容不能借 op 动文件：`ui.open` 只放行 http/https；预览里的 HTML 走白名单消毒。
5. 删除/搬家类 op **宁可停手也不许丢**：块数对不上就停，不删旧文件。
